# prompt-distiller

**AIへの「頼み方の型」を集めて、あなたが普通に話すだけで最適な型を自動で使う仕組み。**
さらに「自分が普段AIに何を頼んでいるか」を履歴から自動で集計するツール付き。

> Mine your own Claude Code history → see what you *actually* ask AI for → distill it into precise, anti-fabrication prompt templates and an auto-router.

---

## これは何？（30秒で）

AIに同じような仕事を何度も頼んでいると、毎回「うまい頼み方」を考えるのが面倒になる。雑に頼むと雑な答えしか返ってこない。

このツールがやるのは3つ。

1. **よく使う頼み方を「型（テンプレート）」にまとめた** … 「リサーチして」「リリース前チェックして」など、用途別に20本以上。
2. **あなたが普通に話すだけで、最適な型を自動で選んで使う** … 「競合を調べて」と打つだけで、リサーチ用の型が裏で立ち上がる。毎回うまい指示を書かなくていい。
3. **自分の使い方を可視化するツール** … 自分のAI利用履歴を読んで「実は自分はAIに何を一番頼んでいるか」を集計する。

そして全部の型に、**「AIに嘘・思いつきを言わせない」ための共通ルール**が入っている（後述）。これが普通のプロンプト集との一番の違い。

---

## なぜ作ったか（短い実話）

作者は「自分はAIで"作る"人だ」と思っていた。でも自分のAI履歴を全部解析したら、真逆だった。

- 解析対象：自分のAIコーディング履歴 **2,927セッション**
- 自動で動くプログラム由来のもの（2,308件）を除くと、**手で打った依頼は619件**
- そのうち最多は「作る」ではなく **「調べて、判断する」(270件)** だった

> プロンプトを磨く前に、まず「自分が何を繰り返し頼んでいるか」を見たほうがいい。思い込みはだいたい外れる。

（履歴を見るだけなら Claude Code 純正の `/insights` でもできる。このツールはその先 ―― 気づいた用途を「毎回ゼロから書かない型」に畳むところまでやる。）

## はじめての人向け：前提のことば

| 言葉 | かんたんな意味 |
|---|---|
| **Claude Code** | ターミナル（黒い画面）で動くAIアシスタント。Anthropic製。 |
| **スキル** | Claude Code に覚えさせる「やり方マニュアル」。フォルダを置くだけで使える。 |
| **履歴** | あなたとAIの会話ログ。`~/.claude/projects` に自動でたまっている。 |
| **プロンプト/型** | AIへの指示文。このリポの `suites/*.md` がその"型"集。 |

**Claude Code を使っていない人へ：** 型はただのテキストです。ChatGPT や Claude のチャット画面にコピペするだけでも使えます（下の「使い方A」）。

## 使い方（やさしい順に3つ）

### A. コピペで使う（Claude Code 不要・いちばん簡単）

1. `suites/recurring-tasks.md` か `suites/product-dev.md` から、使いたい型を1つコピー。
2. その**上に `protocol.md` の中身を貼る**（これで精度が上がる）。
3. `《》` で囲まれた空欄を、自分の状況で埋める（埋められない所は空のままでOK）。
4. ChatGPT / Claude のチャットに貼って送信。

### B. Claude Code のスキルとして使う（自動で型を選ぶ）

```bash
git clone https://github.com/AI-Driven-School/prompt-distiller
cd prompt-distiller
# スキルを Claude Code に登録（フォルダを置くだけ）
cp -r skills/pdp  ~/.claude/skills/
cp -r skills/flow ~/.claude/skills/
```
あとは Claude Code に普通に話すだけ。例：「リリース前にQA固めて」→ 自動で Go/No-Go の型が起動。
（各 `SKILL.md` の中で型ファイルの場所を指定する欄があるので、自分の `prompt-distiller` の場所に合わせてください。）

### C. 自分の履歴を解析する（自分の最頻用途を知る）

```bash
python3 tools/analyze_history.py
```
あなたの `~/.claude/projects` を読み、「自分が手で打った依頼の用途分布」を表示する。
**ローカルで完結し、どこにも送信しない。** 詳細は [`tools/README.md`](./tools/README.md)。

## このツールの一番の特徴：AIに「嘘・思いつき」を言わせない

学習元の違う3つのAI（Claude / Gemini / Codex）に作者のプロンプトを批評させたら、全部が同じ弱点を突いた。

> 「"分からない所は仮定で進めて" が強すぎる。本当は確認すべき情報まで推測で埋めて、それっぽい"砂上の楼閣"を作る。」

AIで一番怖いのは、間違うことより **根拠が薄いのに自信満々で答えてくる** こと。だから全部の型に [`protocol.md`](./protocol.md) のルールを入れた。

- **足りない情報の扱い** … どうでもいい欠落は仮定で進む。重要な欠落は「ここが分からない」と表に出す。
- **数字の扱い** … 出典のない数字は `【推定】` と明記。ありもしない実績は作らない。
- **直すと言ったら測り方もセット** … 「改善しろ」だけで終わらせない。

## FAQ

**Q. 情報が足りないとき、AIは勝手に進む？それとも聞いてくる？**
状況で決まる。
- やり直せる作業（下書き・社内用など）→ **止めずに進む。**ただし「こう仮定した」と必ず明記する。
- 取り消しにくい作業（公開・送信・課金・削除）で、結論を覆す情報が欠けている → **1問だけ確認する。**
- あなたが「質問せず進めて」と言えば → 進む。ただし高リスクなら「この前提でやる、違えば言って」と宣言してから。

要は **指示通り進めてOK。でも"黙って埋める"はしない**（埋めた仮定は必ず見せる）。詳しくは `protocol.md` の「進めるか確認するかの判断」。

**Q. Claude Code を持っていない / 使い方が分からない。**
型は普通のテキストなので、ChatGPT や Claude のチャットにコピペすれば使えます（使い方A）。

**Q. 履歴を解析するのは安全？**
`analyze_history.py` はローカルのファイルを読んで集計するだけ。**外部送信は一切なし。**

**Q. 自分用の型を足したい。**
`protocol.md` の末尾「PROMPTS チェック」（7項目）に沿えば、同じ品質で型を増やせます。
