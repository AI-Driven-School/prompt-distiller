# flow — 繰り返し依頼ルーター

ラフな依頼を、最適なテンプレ(T1〜T10)に対応づけ、共通プロトコルを付けて**そのテンプレとして成果物を出す**。

## セットアップ
prompt-distiller リポの `suites/recurring-tasks.md` と `protocol.md` を参照可能な場所に置き、パスを設定:
- `SUITE_PATH = suites/recurring-tasks.md`
- `PROTOCOL_PATH = protocol.md`

## 手順
1. `PROTOCOL_PATH` と `SUITE_PATH` を Read する。
2. 下表で1本に対応づける（複数該当は最有力1本＋候補を宣言）。
3. §3の住み分けに該当する依頼は発動せず、専用ツールへ譲る。
4. プロトコル(§1)を内部の判断基準にする。
5. `《》` スロットを依頼文・会話から埋め、埋めた値を明示。
6. 入力ゲート: 〈軽微〉は仮定A/Bで前進、〈致命的〉(誰の何のため/判断軸/対象URL・パス/手元の実データ)は最大1問だけ確認。
7. テンプレの出力フォーマット通りに成果物を出す。

## ルーティング表
| 依頼のシグナル | 適用 |
|---|---|
| 競合/市場/事例を調べて・Web調査・「調査だけ」 | T1 リサーチ→レポート |
| この仮説は本当か / 証明 or 否定して | T2 仮説検証(証明×反証) |
| いくらで売れる / 相場 / 評価額 / 単価感 | T3 相場リサーチ |
| この長文をX連投/Qiita/note/要約に | T4 マルチ媒体リパーパス |
| 動画(長尺)の構成/台本骨子を作って | T5 長尺構成 |
| 第◯章のナレーション本文を | T6 章別ナレーション |
| このサムネを評価/改善して | T7 サムネ評価 |
| 〜のコードを探して/現状把握/実装に必要な情報 | T8 現状把握→実装計画 |
| マシンが重い/フリーズ/プロセスがおかしい | T9 環境診断 |
| 何やってたんだっけ / 過去セッション参照 / 続きをやって | T10 セッション要約・継続 |

## 発動しない条件
技術比較リサーチ・記事URL→SNS記事・定常コンテンツ生成・動画のAI生成・財務/KPI/タスク管理は専用ツールへ。プロダクト開発の監査/QA/UX/GTMは `pdp` へ。単純な1問質問・小修正は通常対応。
