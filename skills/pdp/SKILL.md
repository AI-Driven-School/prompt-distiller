# pdp — プロダクト開発プロンプト自動ルーター

ユーザーのラフな依頼を、スイートの最適な1本(P1〜P12)に対応づけ、共通プロトコルを付けて**そのプロンプトとして成果物を出す**。プロンプト本文をそのまま出力せず、それに従って回答する。

## セットアップ
このSKILL.mdと同じ場所、または下記パスに `product-dev.md` と `protocol.md` を置く（prompt-distiller リポの `suites/product-dev.md` / `protocol.md`）。`SUITE_PATH` を自分の環境に合わせて設定:

- `SUITE_PATH = suites/product-dev.md`
- `PROTOCOL_PATH = protocol.md`

## 手順
1. `PROTOCOL_PATH` と `SUITE_PATH` を Read する。
2. 下表で依頼を1本に対応づける（複数該当は最有力1本＋候補を宣言）。
3. プロトコル(§1)を内部の判断基準として採用する。
4. プロンプトの `《》` スロットを依頼文・会話から埋め、埋めた値を明示。
5. 入力ゲート: 〈軽微〉な欠落は仮定A/Bで前進、〈致命的〉(誰が使うか/判断軸/事業モデル/実データ)は最大1問だけ確認。
6. プロンプトの出力フォーマット通りに成果物を出し、末尾に確信度。

## ルーティング表
| 依頼のシグナル | 適用 |
|---|---|
| 画面/機能を一覧化・棚卸し・IA・サイトマップ | P1 画面インベントリ |
| この画面要る? / 削除・統合できる? | P2 単一画面クリティーク |
| 戦略レビュー / 断捨離 / ROI / 技術負債 | P3 CTO兼CPO戦略レビュー |
| インフラ費用 / 最安構成 / スケール時コスト | P4 クラウドFinOps |
| テスト設計 / 観点網羅 | P5 QAテスト設計 |
| リリースしていい? / Go・NoGo / 最終検証 | P6 Go/No-Go判定 |
| このプロンプト(商品)をどう売る | P7 マネタイズ戦略 |
| 導線 / CV / 売れるか / 全画面レビュー | P8 CV導線レビュー |
| 直して通るまで / 実装込みQA | P9 自走実装ループ |
| この出力の品質 / 感動レベルか | P10 アウトプット品質 |
| UI/UXを磨きたい / デザインガイドライン | P11 UI/UX極上化 |
| ショート動画 / 非属人IP量産 | P12 ショート動画IP設計 |

## 発動しない条件
単純な1問質問・小修正、または別の専用スキルが明確に妥当な文脈では発動しない。繰り返しの生の依頼(リサーチ/リパーパス/動画構成 等)は `flow` スキルへ。
